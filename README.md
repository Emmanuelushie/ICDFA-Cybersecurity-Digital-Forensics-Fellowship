# ICDFA Cybersecurity & Digital Forensics Fellowship

This repository contains my ongoing **hands-on laboratory work, weekly assignments, practical exercises, assessments, technical documentation, and project work** completed as part of the **Fellowship in Cybersecurity and Digital Forensics (FCDF)** at the **International Cybersecurity and Digital Forensics Academy (ICDFA)**.

The repository serves both as a **GitHub-based submission platform for my weekly coursework** and as a structured record of my practical cybersecurity learning journey throughout the fellowship.

---

The fellowship is structured around progressive weekly learning activities, practical laboratories, assessments, and projects across multiple cybersecurity and digital-forensics disciplines.

The work documented here is focused on developing practical skills in areas including Linux administration, cybersecurity foundations, network security, security operations, system and network analysis, threat detection, incident response, and digital forensics.

This repository is structured to reflect how technical work is **documented, preserved, reviewed, and submitted** in a professional cybersecurity environment.

## 📘 Repository Contents

### Month 01 – Linux Essentials

**Course:** WADF101

This month covers the foundations of Linux system administration, command-line operations, filesystem navigation, scripting, hardware and storage investigation, networking, and Linux security.

**Weeks covered:**

* Week 01 – Linux Setup, Shell Fundamentals and Filesystem Navigation

## 📂 Documentation Structure

Each course is organized into its respective weeks, with individual laboratories, assignments, assessments, and supporting documentation stored within the relevant weekly directory.

A typical weekly structure may include:

```text
Week-XX/
├── README.md
├── Lab-01/
├── Lab-02/
├── Lab-03/
├── screenshots/
├── outputs/
└── reports/
```

Where applicable, each laboratory or assignment is documented with:

* Objective
* Tools and Environment
* Methodology
* Implementation
* Findings
* Challenges
* Lessons Learned
* Evidence
* Conclusion

The documentation is designed to provide sufficient context for both **academic assessment and professional review**.
